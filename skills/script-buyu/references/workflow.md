# 从来稿到故事剧本

## 先确定需要写什么

完整阅读正文、表格、附件与用户后续修订。建立内部 intake 记录：输入类型、证据、当前期望产物、故事领域、具体背景/版本、叙事视角、核心人物、目标受众、媒介、集数、总时长、不可改变项、可补写范围、关键未知。用户只要一集时不要擅自扩为全季。

把每个故事作为独立项目。叙事视角、是否需要对立人物、是否跨两个世界、两线如何关联、内容比例、集数和时长都从当前需求确定。用户未指定时按本故事目标提出适合的选择，不默认继承上一故事；影响主线的选择先向用户确认。特别是现实与游戏双向影响，只适用于明确要求这种互动的当前作品。

用户明确指定背景可直接作为创作约束；资料不足时保留候选判断，不用固定关键词计数代替理解。游戏、历史和行业细节应符合背景，并服务这个作品选择的叙事方式；不要求所有背景知识都成为冲突机关。模糊且影响主线的缺口问一个具体问题；非关键空白可合理补写并标为创作设定。

输入若是分镜、制作表或带图文档，先识别其中可用于故事的事实与正文，记录未纳入内容。不要原地删除用户的图片或提示词；相关人物形象资料纳入人物设计，镜头和制作参数不混入故事正文。无法可靠读取的关键图片/文本框需要视觉核对，不猜写。

长剧、跨场修订、跨轮恢复及确认稿派生，先执行 [剧情状态与恢复](continuity-control.md)。在当前故事工作目录沿用一份可定位的内部记录；恢复先读取实际源稿、用户新修改、确认范围和未结依赖，不能直接继承聊天摘要里的“已完成”。单句且上下文齐全时只记录必要几行。

## 分配与合并

先按 [唯一统稿与一致性](ensemble-writing.md) 确定当前正文版本、统稿责任和修改范围。需要专业训练基础时按需选用 [代表作品与学院资料](academic-methods.md)；机构、作品和真人方法分别标明来源，不代表真人或学院参与。每条建议须有具体文本目标与处理结果，未合并建议不得与当前正文并列为可交付稿。

统筹先冻结本轮用户约束，再分配研究、故事结构、人物关系、场景、对白、连续性和文档职责。各项产出必须影响具体文本或检查结果。冲突裁决先遵守用户约束、已确认内容、可核事实和本剧世界规则，再在其内考虑整剧意图、人物成立、场景目标与局部表达；领域规则不能为了戏剧效果被悄悄改变。不能把多个建议直接拼成互相矛盾的正文。

实际子代理只有在工具可用且有权限时使用；否则执行分项检查。真实专家方法、功能角色和当前实际代理身份分别记录。内部过程不进入用户文档。

先按 [题材方法入口](genre-methods.md) 有界查询，再按 [场景方法与整剧一致性](scene-methods.md) 选择具体方法并合并为一份正文。每场保留必要的进入／离开状态，连读相邻场景并追查受影响的伏笔和后续场。方法变化不授权改变人物、基调或视觉方向；一致性也不禁止有因果依据的成长、策略变化和类型转折。

## 写作与修订

默认面向AI漫剧，按 [观看节奏与情绪回报](audience-rhythm.md) 明确本剧看点，检查开场入口、持续推进、关键回报和余波。可按剧情选择智谋、能力、关系、幽默、奇观等满足感；不给每剧固定反转次数或秒数，提速后仍回查整剧连续性。

梗概只是输入，不是全季交付。情节驱动的故事先构建因果链；观察、诗性、平行或框架叙事先明确自身的组织方式，再写完整正文。动作、互动和对白按作品需要安排，无对白故事不强加对白。每集标注清楚，并按项目约定处理独立单元或跨集承接；结尾回应本作品的表达目标，不机械强制悬崖结尾。

已有完整剧本优先局部修订；保护未授权改变的人物、事实和结局。用户 Word 修改是新输入，先回读差异，再更新内部结构并递增 revision。内部工作记录至少保存来源、内容摘要/哈希、变更理由、影响的集/场、事实状态和未解决问题。

修订后按 [连续性检查](continuity-control.md) 对比实际前后稿，沿已知依赖追查，并另从正文查找未登记影响。疑似矛盾须给原文位置与中间变化依据；误信、反转和有因成长不能当错误修平。记录更新到新正文，未结的实质矛盾不能标相应范围通过。

完整成稿先输出含全部人物提示词、不嵌人物图的待确认DOCX；按 [character-visuals](character-visuals.md) 在文档外直接展示少量代表人物示例，供确认本剧视觉方向。只改单句、单场或诊断仍按指定范围，不强迫全稿重导出。

分别记录两个确认状态：剧本实际确认消息、DOCX／内容版本及集场范围；视觉方向实际确认消息、示例人物ID及图片、提示词与方向版本。哈希辅助识别文件，不代替用户确认。不从文件名、文内“approved”、历史勾选、导出成功或样本格式满意推断批准。同条指代唯一的自然语言回复可同时确认两项，无需固定口令。仅确认图不等于批准故事；仅确认故事不等于接受示例方向。

两项齐备后按 [storyboard-excel](storyboard-excel.md) 批量生成本次范围人物图并交付Excel；已授权此流程，不重复索取许可。只缺一项时可继续独立工作或内部草稿，不能提前批量全员或交付正式Excel。用户明确只要DOCX时遵守该范围。

无人分支：全稿无角色且没有身份明确的画外／语音人物时，人物示例及其确认记“不适用”，不伪造批准、不造人、不生人物图；文本确认后直接制作Sheet1与保留表头的Sheet2。用户另要求环境美术方向确认时按该明确要求处理，不自动扩大为场景生图。

收到修改后比较实际可见正文、人物提示词及外部图片映射。剧情、对白或范围改变，只重新处理受影响文本确认；提示词中的身份、服装或画风等变化影响示例／角色时，更新对应视觉确认，必要时重出受影响示例。仅修错字或排版，且能证明语义和视觉设定未变，可记录派生关系并沿用确认。不得把Word改动静默回填旧JSON。

Excel列宽、行高及同内容重导出不重启剧本确认。部分角色生成失败保留合格图，只重试失败／受修订角色；同人物示例满足最终设定可直接复用。正式交付按人物ID核对提示词、图像及表格行，不按文件顺序配人，也不借重试改故事。
