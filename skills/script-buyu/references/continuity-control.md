# 剧情状态、修订与恢复

用于长剧、跨场修订、跨轮续写和确认稿派生；是 [workflow](workflow.md) 的执行步骤。单句且上下文齐全的任务只保留必要几行，不创建空台账。本页把现有 [统稿规则](ensemble-writing.md) 落到可回读记录，不增加故事结构、题材或作者配额。方法来源与局限见 [研究依据](continuity-research.md)。

## 1. 找到当前稿，才开始续写

每个项目在已有工作目录维护一个明确的当前记录入口；默认用 `work/continuity.md`，已有等价记录就沿用并记清路径。按 [记录模板](continuity-record-template.md) 裁剪；保留旧版本，入口指向当前源和当前检查进度，不并列两份“最新”。不要把记录写进 Skill 仓库、用户 DOCX 或 Excel。

记录写明相对路径所基于的项目根目录。局部修订可用“固定基稿＋明确覆盖的集场/段落”表示当前正文，记录哪一处由新稿替换，其余仍取哪份源；不能让读者猜两份文件谁覆盖谁，也不为了单场任务强制重导全季。

首次接手或每次恢复时，实际读取：用户最近修改和授权范围、当前正文、记录指向的来源/版本、未结影响项、已确认集场及文本/视觉确认依据。文件修改时间、最大 revision 数字、聊天摘要或旧“完成”标签不能单独决定权威版本。用户改过的 Word 即使版本栏没改，也按新输入回读。

当前源与记录不符时，先比较差异，保留旧记录供溯源，把受影响检查标为“需复核”；不删用户新内容以迁就旧状态。不明确且会改变主线的冲突，问一个具体问题；继续不依赖该答案的工作。记录缺失时从现存正文重建，并标“恢复重建、未继承旧验收”，不能假装曾检查过。

对已按 schema 整理的前后 JSON，可运行 `python scripts/compare_story_versions.py --before work/old.json --after work/new.json` 定位实际改变的字段、场次及顺序。同 revision 内容变化也会列出。工具不理解语义、不找全依赖、不批准版本；外部 Word 先真实回读再用它，不能拿旧 JSON 自证未变。

## 2. 只记录正文能够支持的状态

先区分本剧硬约束、可修改计划和待定事项。硬约束来自用户或已确认内容；Agent 自拟提纲不能自动升格为用户锁定。新作允许在授权内演化计划，但同步回查相关正文；确定不可改的事实与结局不能为适配方法卡而调整。

记录保留稳定人物/场次/事件标识及原文位置，场次换序不复用旧ID指代别的事件。无机器ID的来稿可用集场号+段落锚点，并保留修订对应。下列维度按故事实际需要填写：

| 维度 | 必须分开的内容 | 核对依据 |
|---|---|---|
| 时间与空间 | 实际发生时间/持续时长；观众看到的顺序；地点与移动条件 | 闪回按其实际时间取状态；并行场不能让同一实体无因两地同时行动 |
| 信息 | 故事事实；各人知道/相信/怀疑什么；观众已见什么 | 来源、观察/发送/收到/读到的时点；未发消息不成为对方知识，误信不升为事实 |
| 人物与关系 | 当下策略/情绪；关系许可；长期变化 | 一次表态不证明永久成长；对甲温和不等于对乙也改口 |
| 物件与能力 | 所有者/持有者/位置；资源、伤势、限制与恢复 | 谁何时转交/消耗/获知/治愈；拿到物品不等于获得使用或转交许可 |
| 承诺与伏笔 | 提出者、对象、范围、条件、期限；计划回收与已写回收 | 只同意一晚不扩成长期；有意留白保留其意图与可用依据，不强制解答每个谜 |
| 主线与选择 | 本剧承诺、关键选择者、代价承担者、实际后果 | 配角建议不必夺权；主角只剩附和且原核心责任被转移则须审查授权 |

每个关键变化写成“进入状态 → 本场可见依据 → 离开状态”，绑定场段。未来提纲标为计划，不能提前写成人物已经知道或事情已经发生。关键条件尽量保留原句和位置；简记不是新正典，省略限定词后必须回源。

## 3. 写作与多方法合并

写当前场前只取：本轮允许改变的范围、本场必要进入状态、相关前文原句和本场任务。为铺垫读取的后续计划明确标“尚未发生/尚未揭示”。无需整库作者卡或全台账灌入上下文。

写完由唯一统稿者核对实际正文后再更新状态，不能只把提纲抄成“完成”。新增承诺、物件、伤势和秘密写入记录并连接使用处。对不涉及状态变化的普通交流允许“不变”，不要制造冲突填表。方法可变、语气可变，选择与后果须符合本剧；快节奏和爽感不能跳过代价、知识来源或能力条件。

## 4. 改一处，查实际受影响的整条链

1. 先写修订目的和授权范围，对比实际前后稿；区分纯措辞、剧情语义、人物视觉和版式，拿不准时记待核，不自动当错字。
2. 从变更事实找所有使用处：称谓/别名、物件及代词指代、依赖该信息作出的判断、后续选择、回收与结局。沿“依靠它成立”的关系继续追查，不能固定只查前后两场。
3. **另做一次从正文出发的阅读**，不要只检查已列依赖。完整授权稿逐集通读；局部修订时读取可获得的关联上下文，但不擅自改授权外正文。检索定位只作辅助，不能以未搜到同名词证明没有隐含因果依赖。关键远场缺失时明确未验证范围。
4. 每个影响项记录“源场段/变化 → 受影响场段 → 保持/已修/待处理/不涉及及依据 → 回读结果”。“不涉及”须能说明为什么该后果不依赖变化；不能仅打勾。已经修复的项回读新正文后才关闭。
5. 正文与记录对应到同一版本后保存：完成的集场、仍未结项、下一步。未解决的实质矛盾不能标相应范围通过；授权外需要修改时指出最小变更，继续可独立推进内容。

例如前场把“钥匙赠与”改“周五前保管、不能转交”，后场的转交和开门都须回查；即使后场只写“她把它递过去”，也不能因没有“钥匙”二字漏查。禁止为迁就末场而倒改用户锁定的前提，或无因增添第二把钥匙。

## 5. 先判问题，再最小修复

疑似矛盾保留两处实际原文位置，以及中间可能解释变化的场段；说明冲突发生在同一实际时间/条件下的何种事实。不存在第二处冲突陈述的漏铺垫/无因结果，改为记录已声明前提、当前结果和缺少的连接，不能捏造矛盾句。

判定分为：**确认矛盾、成立的变化、有意信息隐藏/不可靠叙述、证据不足**。先核误信、谎言、回忆、梦境、视点、时间流逝、规则例外及本轮授权。不要把角色误认改成全知、把反转提前解释、把有因成长恢复原状。声称“有意安排”也需正文线索或用户创作意图，不能成为所有错误的借口。

修复优先撤销越权修饰或修正受影响场内表达；在授权内补写必要连接时同步核查新事实、时长预算与后续影响。确须改变已锁主线/事实/结局时提出冲突，不自行改锁定条件。每次修复回读差分，检查有没有“修好一处、新增一处”，不盲目循环自动改稿。

## 6. 确认后派生与完成证据

按 [Excel交付](storyboard-excel.md) 执行。保留内部两向对应：源稿每次事件/发言出现在哪些镜行；目标镜行来自何处或仅补了什么非因果表现。两句相同原话也有不同发生位置；同句拆镜按顺序拼回，核说话者、声道与揭示时点。新增目标句或无来源因果动作必须显露出来，不能只证明“原稿都能搜到”。

用实际重新打开的 XLSX 单元格核对，不用导出前内存草稿冒充回读。动作、主画面、运镜和台词一起检查：粒子若暗示新能力、特写若提前泄露凶手、镜头省略若让许可扩大，均是语义问题。只做文本脚本，不为本检查启动试拍或视频生成。

交付前保留实际检查范围、版本、发现及处理、未检查部分。分别说明结构校验、正文语义审读、映射原文核对、视觉排版检查的结果，互不代替。长稿检查未完可保存阶段稿，不能宣称全稿一致。已有确认按受影响范围处理，纯版式且内容未变不重启故事确认，视觉确认也不被无关文字修订清空。

维护本能力时使用 [评测办法](continuity-evaluation.md)；资料和示例本身不证明运行永不出错。
