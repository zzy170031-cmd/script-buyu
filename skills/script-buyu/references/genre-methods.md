# 题材方法库的选择、计数与分批维护

当前已补齐26个核心题材入口，每类作家与导演合计至少10位不同自然人、覆盖两种职业；新增以最初c204898人物基线为准，同人有逐类依据时可复用，跨类不重复增加全库人数。另有31个组合/环境/结构入口，例如宫斗、谍战、末世、穿越、重生、系统、校园、医疗、律政、电竞；明确列出可选择的基础类，不假装各自另有独立十人池。26类是可扩展的AI漫剧工作目录，不是所有未来题材的终极全集。

核心范围、逐人名单与绑定保存在本Skill的 [题材索引](../data/genre-index.json)，按下方查询工具读取所需记录，不整库加载。分类采用多入口，先确定本剧中心任务和世界背景，再选实际需要的组合。类型交叉和分类局限参考 [BFI关于类型边界的说明](https://www.bfi.org.uk/features/genres-where-draw-line)，具体26类由本库按用户用途整理，不是BFI官方清单。

## 创作时怎么选

1. 先按 [场景与整剧一致性](scene-methods.md) 明确本剧事实、状态、视点、基调、视觉方向和当前问题；再查题材。爱情中的枪战可以分别检索两个入口，不能因为检索到两类就让同一卡自动适用两类。
2. 用下面的只读命令查看资料。默认返回3位只是便于阅读，可调整，实际使用可以为零，不要求每场调用固定数量或某位主导师。

```text
python scripts/query_methods.py --list-genres
python scripts/query_methods.py --list-routes
python scripts/query_methods.py --genre 悬疑 --query "证据 揭示" --limit 3
python scripts/query_methods.py --genre 爱情 --query "关系 障碍" --stage draft
python scripts/query_methods.py --genre 枪战 --query "镜头 人物" --stage confirmed_translation
python scripts/query_methods.py --genre 宫斗 --query "关系 选择" --limit 3
```

3. 阅读返回的资格/职责证据、具体贡献、本人观点或我方原作分析、题材适配理由、限制和阶段。按 [选组与统稿](ensemble-writing.md) 比较互补及冲突，不按名气或结果顺序组队。检索不证明最优；无结果可换查询或直接创作，不放宽阶段。组合查询的总返回数也受limit限制，同人去重；基础类是可选路径，不要求全部混入故事。
4. 把选中的方法落在具体场景、人物或镜头，并按 [AI漫剧节奏](audience-rhythm.md) 检查看点和回报。短场可以只负责建立异常，后场再兑现；不强迫每场完成“期待—阻力—选择—回报—后果”全套。
5. 统筹合并为一份正文，沿事实依赖检查前后场、跨集承接与未兑现伏笔。镜头表达可变化，人物身份、世界规则和已确认内容不能随着作者名字切换。

## 常用称呼怎样接到现有入口

下表帮助理解选题，不新增核心类、独立人物池或脚本别名。先保留用户所说的背景、基调和故事目标，再用右侧已登记名称查询；需要多个核心类时分别查询，只取实际相关的方法，不将“科幻＋动作”等说明当成一个CLI题材名。

|用户称呼|已有查询入口及选择边界|
|---|---|
|城市／都市|可查“都市”组合；城市首先是环境，仍按本剧主要问题选爱情、职场、社会现实或其他相关核心类。都市悬疑可直接查悬疑，不因组合列出爱情／职场就添加这些剧情。|
|热血战斗|通常先查“动作”；热血是基调，不是新题材池。有枪械交战才加“枪战”，有战争组织与背景才加“战争”，不强制所有战斗写成战争。|
|悬疑|直接复用“悬疑”，按具体证据、解释与揭示问题选方法。|
|爱情|直接复用“爱情”，按人物关系与实际选择取舍；不因有城市背景就改变主问题。|
|童话|可查“儿童童话”组合中的奇幻、家庭、冒险路径；受众年龄与理解范围另按本剧确定，童话不自动等于低龄，家庭也不自动等于儿童适宜。|
|科幻战斗|分别查“科幻”和“动作”；科学／虚构规则影响战斗选择时一起核对，实际涉及战争才查“战争”。|
|科幻|直接查“科幻”；可以写社会、伦理、关系或发现，不默认含战斗、战争或英雄升级。|
|星战|若泛指太空战争／太空歌剧，可查“太空歌剧”组合，以科幻为基础，冒险与战争按实际内容选。除非用户明确指定IP，不自动继承《Star Wars》的角色、设定和正典。|

这些称呼导航不改变下文的查询回退、阶段和确认边界。原词未登记或当前阶段无命中时，不声称命中已有专家，也不放宽阶段；使用明确的已登记入口或现有手动导航，保持原题材和故事意图。

## 来源和人数怎样计算

[方法正文](../data/story-methods.json)保存来源与方法；[题材薄索引](../data/genre-index.json)保存规范person_id、别名、作品、来源引用、方法引用及逐题材适用理由，不复制每张卡到多个题材文件。

- 既有基线为c204898；旧来源及对应真人不算本次新增。罗素兄弟原来虽是一条team记录，Joe和Anthony两人都排除。Disney与Animation Guild团队不是新增自然人。
- 同人兼编剧与导演只计一人，同人有两个来源或多个方法也只计一人。同人跨题材可各计一次，但必须每类分别具备对应作品与正文支持的适用理由，总独立人数另算。
- 当前索引每人每题材只有一条绑定，绑定引用一个来源及其方法。同人同类的第二来源先存入方法库，不另建重复人物绑定；需要多来源绑定时先升级结构、校验与测试，再接入，不能用重复条目增加人数。
- 本人公开观点、我方操作化、题材关联推断分别记录。读到相关问答记相关段落已读，活动报道短引语记excerpt，不冒称读完整本书、讲座或嵌入视频。
- 来源页、自然人、方法及逐类绑定分别计数。3张古典文本卡明确primary_work_analysis，是我方对已读原作片段的分析，不能以作者姓名称其本人教学。资格不足的candidate或rejected绑定不进入人数和查询。
- `source_ready`仅表示当前有效绑定的人数与两类职业符合资料下限；不证明审美、现实专业资格、真人参与或观众效果。正文证据仍须按记录的定位复核。
- 方法可以机制重叠，但需说明何时适用、怎样操作和失败边界。不同姓名不等于不同能力；不为凑独创机制数量另设配额。

## 扩充节奏与恢复

按“查缺口→原始来源→具体方法→逐题材绑定→检索反例→整剧边界复查”追加，优先当前真实选题的缺口。每批记录batch_id、父版本、人数、来源、绑定数、排除项和验证状态；当前三组研究归入同一可追溯首批。无新证据时停止争论或保留候选，不凭反复摘要升级可信度。

只读检索按origin→source→method→binding处理active、candidate、isolated。共同访谈页面的origin被隔离时，其全部相关人物方法暂停；单一发言有误只隔离该source即可，无关资料仍可用。origin以规范URL归并当前页面，转载同源仍需人工识别并归并，页面数不等于独立印证数。多来源方法任一依赖失效即暂停，待核实支持关系；悬空引用、身份冲突等共享结构损坏须先修复。

`--list-genres`实时计算人数：低于10或缺写作/导演覆盖时显示partial，不继续声称达标。失效卡修改有版本和影响范围，修复后重新激活相应依赖；无法补证则保留缺口。回滚使用对应提交或仅撤销该批文件变更，不重写用户故事、删除旧交付或强推Git历史。

## 阶段与交付不扩张

draft/authorized_revision允许本轮授权的正文工作。阶段按具体方法内容判定，不能按作者是否导演授予。涉及新动机、故事重排、删改台词的正文构造方法不进入confirmed_translation结果。

题材检索中仅G006/G020/G024/G025/G028/G031提供独立confirmed_steps；确认后查询用这些步骤替换草稿步骤。手动选用的D01–D08也提供确认后专用步骤，按 [文本场面组织](text-direction.md) 使用，不因此新增题材检索结果或人数。新增X卡仅用于draft/authorized_revision；原作分析也无额外改写权限。需要改写时指出具体问题及影响，按当前授权处理。校验器对全部声明确认后阶段的卡检查专用步骤，不再只检查题材绑定。

检索无结果时，输出fallback仅提供 [台词核心](dialogue-craft.md)、[专业支持](genre-professional-support.md) 和场景修订的手动入口，不是命中的方法或已核专家。未知题材仍明确报未登记并指向这些入口，不偷偷替换题材或放宽阶段。--list-genres分别报告去重总人数、writer、director和兼任人数；达标口径仍为合计十名且两类都有，不是两类各十名。

DOCX仍含完整人物提示词且不嵌图，少量代表人物示例在文外展示。实际文本与视觉方向确认后，批量人物图进入两表Excel。新增资料不触发全员重画、第三张方法表或视频制作，不引入真人代理或自动多Agent会议。
