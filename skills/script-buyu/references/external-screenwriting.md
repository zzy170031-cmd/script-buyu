# 外部剧本写作方法：按问题使用

外部模块是可选方法，不因被收录就全部生效。不声称已核对其所引所有书籍，也不把作者自述当成专家资质或本稿质量证据。原作者/原作仅用于准确归属方法，不能据此假称真人参与。

## 从创意到可写的故事

**命题与主题**（sw-premise-theme）：把当前故事压缩成“谁在什么条件下追求什么、遇到什么阻力、必须作何选择”。主题先作为待探索的问题，在相反选择及后果中检验，不让所有人物替作者说结论。抒情故事可以用感知变化或关系变化组织，未必需要任务型目标。

**故事结构**（sw-story-structure、sw-truby-anatomy）：围绕人物的选择和后果排列事件，再检查关键转折是否由此前行动积累而来。三幕、节拍表或成长旅程都可用于诊断；不要先填固定页码再为凑格子添加剧情。重排时保存原稿事件映射，特别核对观众何时知道关键信息。

**类型承诺**（sw-genre-anatomy）：明确受众期待的体验，例如悬疑中的信息差、喜剧中的预期偏差、爱情中的关系选择。类型混合时说明主导体验和切换依据；只添加“热血”“治愈”等形容词不算完成类型改写。

## 人物、场景与对白

**人物与对立**（sw-character-conflict）：区分眼前目标、长期需要、习惯策略和承受不起的代价；给重要对立方同样具体的行动能力。用一组关键选择检查弧线，不把心理学术语当人物诊断，不强制所有角色改变或更好。

**场景设计**（sw-scene-craft）：写前说明此场需要发生什么；写后比较人物处境、关系、信息或情绪的变化。若一场只传递解释，考虑让信息在行动中显现。观察、停顿或日常场景以其审美和情感功能判断，不因缺少反转就删除。

**对白与潜台词**（sw-dialogue）：为每段话确定人物正在做什么——试探、回避、交换、挽留、掩饰等。核对人物知道多少、对谁说、为何现在说，以及对方的行为回应。删去重复的信息功能，保留因关系变化而必要的重复。可用替换说话人检查声音是否同质；不能把语气词差异当人物塑造。

**喜剧**（sw-sitcom-comedy）：先明确人物认真对待的目标，再设计其策略与处境的错位；检查铺垫、预期、反应和代价。笑点应符合人物的知识和性格，不靠突然变笨解决情节。短篇或非喜剧项目不加载这一模块。

## 长篇、分集与创作协作

**剧集引擎**（sw-series-engine-bible）：区分本集能收束的问题与可持续产生新故事的关系/环境压力。维护当前人物状态、世界规则、尚未兑现的承诺和季终目标。先按用户指定集数与篇幅规划，不能把“可持续”变成无限续写。

**单集和季结构**（sw-series-structure）：每集既承担当集体验，也按约定推进季线。记录伏笔首次出现、观众已知、角色已知和回收位置；独立单元不强加连续主线，流媒体剧集不机械套广告断点。全季交付必须写完每集正文，规划表不能替代成稿。

**中文剧集实践**（sw-chinese-series-practice）：将梗概、分集大纲、分场和完整剧本分清。改编时列出保留、合并、删除及改写的情节与人物，并说明因果影响；既有 IP 和历史材料的核实交给当前研究流程，不假设上游案例授权覆盖新项目。

**创作讨论**（sw-writers-room）：把意见分成事实错误、因果缺口、人物选择问题和表达偏好。每条修改建议定位到场次与预期效果，统筹解决相互冲突的意见。角色职责不等于真实多人参与；是否调用子代理遵守宿主和当前用户授权。

## 表达传统、诊断与修订

**地域与表达传统**（sw-japanese-screenwriting、sw-korean-french-screenwriting）：比较动作、留白、情绪积累和关系压力的不同组织方式，选择符合本作的办法。不要把国家、作者或流派当成固定人格公式，也不要为模仿而复制既有作品桥段。

**案例分析**（sw-american-case-studies、sw-series-case-studies）：只提取需要验证的结构问题，例如铺垫何时足够、揭示如何改变判断、一次让步如何改变关系。记录适用条件和不适用之处，避免以成功作品名气替代本稿检查。不复制出版剧本全文及其译文。

**格式与改编**（sw-format-adaptation）：先遵守用户所选交付格式，区分事件、动作、对白、旁白和必要声音。故事稿不自动增加摄影参数或制作任务。若改媒介，检查叙述信息是否需要转为动作、对白或必要旁白，不直接套“一页等于一分钟”。

**跨轮工作状态**（sw-workflow）：长项目在工作记录保存当前版本、锁定事实、已完成集场、未解决问题和下一步；恢复时先读当前可见稿及用户新修改。工作状态不得替用户确认作品，也不得触发图像、视频或发布流程。

## 用法记录

每次采用一项方法，内部保留“当前问题 → 方法 → 改动的集/场 → 读回结果”。如果它不能改变写作决策或指出具体问题，就不必加载。对同一场通常选择最相关的两三项；不要把全库拼成每场必须满足的检查清单。
