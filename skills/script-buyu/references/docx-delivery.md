# 剧本DOCX交付与修订

第一阶段交付完整故事和人物提示词，不嵌人物图。图片先以文外少量代表示例确认方向，之后批量生成并进入Excel，见 [character-visuals](character-visuals.md)。

先核本轮授权的实际正文：梗概里承诺的关键改变是否在场面里发生，已有完整稿是否被概要替代，新增写作是否越过来稿范围。仅要正文、局部修订或忠实排入DOCX时，沿用该范围和现成结构；不为符合完整剧本schema补编人物经历、梗概或视觉设定。完整剧本委托才整理下述默认栏目。对照实际正文完成这一核读，再导出；结构验证不代这一步。

有片长要求时，从正文划分连续呈现段：先识别实际播读的对白/旁白、播放的录音和必要声音，再判断动作与它们并行还是先后。估的是呈现时间，不读动作说明来算片长；同次发言跨镜只计一次，录音重复播放按每次实际长度计，不能把“最长20秒”当每次必20秒。串行呈现段相加；部分重叠按实际声画区间扣除重复时间，仅共同起点、完全重叠的一组才可用较长者代表。持续环境声不另加时间，不给“没接话又整理幕角”等再叠一份静默。静场看人物/观众正在关注什么及自然结束点；赶路、往返和等候明确连续呈现还是省略，不把未写等待任意拉长。给合理区间及关键演绎假设；紧预算或精确要求才计时读演或据已有材料判断。明显不足时回到已授权的经历、接收或行动修订，不能靠慢念、无事等待或改预算字段凑达标。

文字数据遵守 `schemas/screenplay.schema.json`。人物的 `visual_prompt` 用于新成稿第五列“人物形象提示词”；有角色时为全部列入人物表的人写完整非空提示词。为兼容旧四列稿，schema允许省略该字段，但一份数据不能只给部分人填写。无人物故事保留空表，不造人物。

`generate_story_docx.py` 直接排版四列旧稿或五列新提示词稿，不生成或嵌入图片。Agent负责写作；标题、集／场编号、预算及动作对白保留语义样式和稳定书签。提示词自动换行，按内容安排列宽、行高与分页，不靠缩到难读字号容纳。

`extract_story_docx.py` 严格回读可见正文及支持的四列／五列表，完整保留多段提示词。用户删空提示词、改为未知表头、插入图片、修订标记或未知结构时，报告并核对；不回填旧文本，不忽略第五列，不自动降为四列表。

外部或历史含图DOCX用 `read_source_docx.py` 展开段落、表格和辅助部分，并视觉核对图片、文本框等。它不访问外链，也不等于排版预览。历史图片可提取为外部候选资产，但不因存在于旧稿就自动获新视觉方向批准。保留原件，另存新格式。

旧 `embed_character_images.py` 只为明确要求维护旧含图版时保留，不在新默认交付中运行。它只接受旧四列表，新五列提示词稿应被拒绝，不能覆盖已有提示词或擅增第六列。

每次修改另存新路径并递增revision。导出前验证结构，导出后严格回读，将动作、对白、旁白和声音按发生顺序与本次源稿逐段比较，再核人物表及多段提示词；检查新DOCX没有嵌入人物媒体且全部提示词存在。文件先写临时路径，关闭后以不覆盖方式发布；文件系统不支持现有安全写入方式时说明错误并换允许的本地工作目录，不退化为覆盖原稿。

有文档渲染器时逐页检查字体、换行、人物表长文本、分页及对白顺序。未完成渲染时明确“结构检查通过，视觉排版未验证”。测试文档不作为用户作品交付。`tests/fixtures.py`的《远灯驿站》是程序输入，其120=60+60仅测预算求和；短对白、提示词修改片段和机械镜行不证明完整作品、合理片长或镜头表演。保留原夹具，另用已授权真实稿核文稿链，不能扩写夹具后冒充原回归证据。完整人物提示词须逐份独立可读：从当前设定写出最终全文，不把“改雨衣”“保留原年龄”“同上”等修改指令当成完整设计。用户暂缓图片时继续文字出口，图片项目按暂缓状态记录。

交付后按 [workflow](workflow.md) 分别记录剧本及文外视觉方向确认。正文“已批准”、文件名或导出状态不是授权；同条明确回复可确认两项。缺任一项时保留草稿、继续独立工作，不提前批量人物图或正式Excel。

无人稿按workflow的无人分支：人物示例及确认标“不适用”，不等人物图批准；文本确认即可输出分镜及空人物表。这个分支不授权场景生图。

## 导出用途与交付选择

DOCX导出同时写入包内用途标记和同名`.identity.json`旁置记录，绑定当前文件哈希；回读JSON继承用途并生成自己的绑定记录，正文schema不增加用途字段。已知fixture内容/登记身份与工程来源优先，不能用改标题、换文件名或声明work_draft转正；普通作品含“测试”等词不据此归类。工程样件仍可导出/回读，旧四列输入继续兼容。标记只说明来源用途，不证明正文、提示词、版面或片长合格。

发送作品前实际运行`select_story_delivery.py`选当前DOCX/JSON或有来源绑定的XLSX，工程/未知身份不能进入作品出口。XLSX等由外部工具派生时，以实际源文件`--source`先用`--record-only`记录用途和文件哈希，带旁置记录保存；复制后无记录的未知文件须核实际来源，不按路径猜成品。原样件、旧记录不改写；真实委托及内容核验是另一条链，不能只重命名测试件。用户文稿不增加审计表列，旁置记录为内部选择依据。
