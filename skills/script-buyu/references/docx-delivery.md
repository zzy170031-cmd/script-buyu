# 剧本DOCX交付与修订

第一阶段交付完整故事和人物提示词，不嵌人物图。图片先以文外少量代表示例确认方向，之后批量生成并进入Excel，见 [character-visuals](character-visuals.md)。

文字数据遵守 `schemas/screenplay.schema.json`。人物的 `visual_prompt` 用于新成稿第五列“人物形象提示词”；有角色时为全部列入人物表的人写完整非空提示词。为兼容旧四列稿，schema允许省略该字段，但一份数据不能只给部分人填写。无人物故事保留空表，不造人物。

`generate_story_docx.py` 直接排版四列旧稿或五列新提示词稿，不生成或嵌入图片。Agent负责写作；标题、集／场编号、预算及动作对白保留语义样式和稳定书签。提示词自动换行，按内容安排列宽、行高与分页，不靠缩到难读字号容纳。

`extract_story_docx.py` 严格回读可见正文及支持的四列／五列表，完整保留多段提示词。用户删空提示词、改为未知表头、插入图片、修订标记或未知结构时，报告并核对；不回填旧文本，不忽略第五列，不自动降为四列表。

外部或历史含图DOCX用 `read_source_docx.py` 展开段落、表格和辅助部分，并视觉核对图片、文本框等。它不访问外链，也不等于排版预览。历史图片可提取为外部候选资产，但不因存在于旧稿就自动获新视觉方向批准。保留原件，另存新格式。

旧 `embed_character_images.py` 只为明确要求维护旧含图版时保留，不在新默认交付中运行。它只接受旧四列表，新五列提示词稿应被拒绝，不能覆盖已有提示词或擅增第六列。

每次修改另存新路径并递增revision。导出前验证结构，导出后严格回读比较；检查新DOCX没有嵌入人物媒体且全部提示词存在。文件先写临时路径，关闭后以不覆盖方式发布；文件系统不支持现有安全写入方式时说明错误并换允许的本地工作目录，不退化为覆盖原稿。

有文档渲染器时逐页检查字体、换行、人物表长文本、分页及对白顺序。未完成渲染时明确“结构检查通过，视觉排版未验证”。测试文档不作为用户作品交付。

交付后按 [workflow](workflow.md) 分别记录剧本及文外视觉方向确认。正文“已批准”、文件名或导出状态不是授权；同条明确回复可确认两项。缺任一项时保留草稿、继续独立工作，不提前批量人物图或正式Excel。

无人稿按workflow的无人分支：人物示例及确认标“不适用”，不等人物图批准；文本确认即可输出分镜及空人物表。这个分支不授权场景生图。
