# 剧本 DOCX 交付与修订

内部数据遵守 `schemas/screenplay.schema.json`。最终默认只有一个DOCX，包含项目定位、梗概、人物及弧线、世界规则和全部分集的逐场动作/对白。状态为待用户确认，不附镜头或生成提示词。

Agent负责完整写作，`generate_story_docx.py`只排版已完成正文。标题用Title，集标题显示序号、集ID、集名和预算；第二集起另起一页。人物表只含人物ID、姓名、人物设定、人物弧线。页宽、字体与表格宽度不应挤压长文本，长表重复表头。

本格式在动作/对白段落放稳定书签ID并使用语义样式，不把隐藏JSON当成正文。`extract_story_docx.py`读取用户可见文字；新增未知段落、结构变化、图片、修订、字段或嵌入对象都会阻断严格回读，必须核对后整理，不能静默丢弃。正文写“已批准”不产生任何后续权限。

外部DOCX用`read_source_docx.py`展开段落、表格和辅助部分供Agent阅读。读取器报告图片/文本框/修订/外链，且不访问外链。它不是忠实排版预览；有关内容需要实际查看。未知或图像主体资料不能只靠文本提取下结论。

每次修改保存新路径，revision递增，核对已授权变化和未改内容。导出前验证内部结构，导出后严格回读与内部数据对照。项目时长和各集时长只是预算核算。文件先写到同目录临时路径，完整关闭后以不覆盖方式发布；需要文件系统支持硬链接。文件系统不支持时报告错误并改用允许的本地工作目录，不退化为可能覆盖的写入。

有宿主文档能力时，用其允许的渲染器生成内部页面预览并逐页检查：字体、换行、表格、分集换页、对白顺序。依赖缺失时必须说明“结构检查通过，视觉排版未验证”，不能伪造渲染通过。测试输出不作为用户剧本交付。

交付后停止，不生成批准凭据、导演结构、制作JSON或Excel。需要其他阶段时由用户另行选择工具或Skill。
