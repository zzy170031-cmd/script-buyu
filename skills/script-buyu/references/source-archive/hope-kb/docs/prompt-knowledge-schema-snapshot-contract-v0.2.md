# Prompt Knowledge Schema Snapshot Contract v0.2

## Status

Status: docs-only contract proposal for `hope-kb` v0.2.
Thread: HopePrompt KB graph schema and snapshot contract.
Repo boundary: `hope-kb` only.
Runtime goal: improve storyboard prompt quality through verified Prompt
knowledge, not image generation, video generation, default GraphRAG, hybrid
search, rerank, runtime ingestion, or runtime summarization.

This document does not modify seed JSON, migrations, snapshots, validators,
`E:\codex\hope`, desktop code, or provider/runtime code.

## Route Boundary

The current route keeps the LLM Wiki architecture as four layers:

- `raw_layer`: raw exports, raw notes, raw prompt text, source workbooks, and
  unreviewed captures. It is never a runtime-consumption layer.
- `wiki_layer`: reviewed human-readable LLM Wiki pages derived from raw
  material. It may preserve narrative context and source explanation, but it
  is still not a runtime-consumption layer.
- `schema_layer`: machine-readable Prompt knowledge objects normalized from
  the wiki layer, current v0.2 seed assets, or both.
- `snapshot_layer`: immutable, verified, hash-bound runtime selection surfaces
  compiled from eligible schema objects.

Runtime consumers may read only a verified `snapshot_layer` activation. They
must not query `raw_layer`, `wiki_layer`, seed JSON, source files, quarantine
stores, or full schema catalogs at request time.

## Object Envelope

Every Prompt graph object that enters `schema_layer` uses the same envelope:

```text
schema_layer: prompt_knowledge_schema.v0.2
snapshot_layer: prompt_knowledge_snapshot.v0.2
schema_id: <schema_type>:v0.2:<stable_object_key>
schema_type: <controlled object type>
version: v0.2
source_wiki_ids: [<wiki page ids or empty when no wiki page exists yet>]
source_ids: [<source_register source_id values>]
source_sample_ids: [<sample_id or mapping_id values when applicable>]
required_fields: [<fields required by this schema_type>]
validator_gate: <named compile or validation gate>
runtime_exposure: <none | gate_only | selected_ids | summary_only | ids_and_summary>
snapshot_eligible: <true | false>
review_status: <accepted | accepted_limited | candidate | quarantined | rejected>
effective_confidence: <review-derived confidence or empty>
```

Rules:

- `schema_id`, `schema_type`, and `version` are required for every object.
- `source_wiki_ids` are required once wiki pages exist. During the current
  seed-first v0.2 bridge, an object may use an empty `source_wiki_ids` list only
  if `source_ids` and `source_sample_ids` bind it to committed seed/source
  assets.
- `source_ids` must point to reviewed source-register entries or an approved
  future normalized source adapter.
- `required_fields` must be machine-checkable by `validator_gate`.
- `runtime_exposure` must be explicit before `snapshot_eligible=true`.
- A schema object can exist for audit or planning while
  `snapshot_eligible=false`; it cannot enter the active runtime snapshot.

## Prompt Object Set

### `prompt_sample`

Purpose: a reviewed storyboard prompt example or example-derived knowledge
node.

Current v0.2 source basis:

- `golden_sample_library`
- linked `golden_sample_failure_mapping`
- linked `golden_sample_repair_mapping`
- source register and provenance entries

Required fields:

- `schema_id`
- `schema_type=prompt_sample`
- `version`
- `source_ids`
- `source_sample_ids`
- `sample_id`
- `machine_id`
- `library_status`
- `sample_type`
- `shot_intent`
- `scene_taxonomy`
- `camera_language`
- `continuity_rule`
- `negative_constraint`
- `quality_gate`
- `validator_gate`
- `runtime_exposure`
- `snapshot_eligible`

Snapshot eligibility:

- `library_status=official`
- positive few-shot eligibility is true
- not reserve, candidate, quarantined, or rejected
- not marked as a negative fixture for positive few-shot selection
- required coverage fields are present
- source bindings pass source integrity checks

Runtime exposure: `ids_and_summary` only. Allowed runtime fields are
`selected_sample_ids` and a compressed `kb_context_summary`. Raw full rows,
raw `prompt_body`, raw source text, source-register dumps, and overlay JSON are
not exposed.

Purpose: compact rule knowledge that can guide prompt construction, repair, or

Required fields:

- `rule_id`
- `schema_id`
- `schema_type=prompt_rule`
- `version`
- `rule_scope`
- `source_wiki_ids`
- `source_ids`
- `required_fields`
- `validator_gate`
- `runtime_exposure`
- `snapshot_eligible`

Snapshot eligibility:

- rule text is reviewed and source-bound
- rule scope is one of the controlled Prompt graph scopes
- no rule conflicts with negative constraints or source policy
- rule is not generated by runtime summarization

Runtime exposure: `ids_and_summary` only through `selected_kb_rules` plus

- `version`

- `validator_gate`

- `snapshot_eligible`

Snapshot eligibility:

- linked samples or wiki pages exist
- failure codes are controlled
- failure pattern is reviewed as either blocking, warning, or repairable
- negative fixtures cannot become positive few-shot samples

Runtime exposure: `gate_only` or `ids_and_summary`. The runtime may receive a
compact warning or selected failure-pattern IDs. It must not receive raw

## Schema Layer Admission

An object may enter `schema_layer` when all conditions hold:

- It has a stable `schema_id`, controlled `schema_type`, and `version`.
- It has `source_wiki_ids` or seed/source bindings through `source_ids` and
  `source_sample_ids`.
- Its `required_fields` are populated or explicitly marked not applicable.
- Its `validator_gate` is named and maps to a current or planned validator.
- It has explicit `runtime_exposure`.
- It does not carry secrets, API keys, provider tokens, credential headers, or
  local credential values.
- It does not depend on runtime network fetching, runtime auto-ingestion, or
  runtime LLM summarization.
- If it uses raw prompt material, that material remains in raw/wiki/source
  layers and is not marked for runtime exposure.

`schema_layer` may contain candidate, reserve, negative, or audit objects, but
those objects must have `snapshot_eligible=false` unless they satisfy the
snapshot rules below.

## Snapshot Layer Admission

An object may enter `snapshot_layer` only when all conditions hold:

- `snapshot_eligible=true`
- `review_status=accepted` or `review_status=accepted_limited`
- `effective_confidence` satisfies the gate for its selection surface
- source minimum fields are present or normalized:
  `source_id`, `source_type`, `url_or_path`, `content_hash`, `review_status`,
  `effective_confidence`
- source bindings pass the snapshot/source integrity contract
- `validator_gate` passes
- `runtime_exposure` is one of the allowed runtime-exposure modes
- reserve, candidate, quarantine, rejected, and negative-fixture objects are
  excluded from positive few-shot runtime selection
- activation binds `seed_bundle_hash`, `manifest_hash`, `snapshot_hash`, and
  `index_hash`

Snapshot storage and runtime exposure are separate concepts. A verified
snapshot may carry internal gate or audit objects, but the runtime selection
view must expose only the fields allowed by `runtime_exposure`.

## Runtime Exposure Contract

Runtime may consume only a verified active snapshot and its verified runtime
selection index.

Runtime fields are split into three artifact classes. A field allowed in one
class is not automatically allowed in another class.

### `prompt_payload`

`prompt_payload` is the model-visible payload used for prompt construction.
It must remain summary-only plus selected IDs.

Allowed fields:

- `resolved_intent`
- `selected_sample_ids`
- `selected_kb_rules`
- `selected_object_ids`
- `kb_context_summary`
- `fallback_reason_code`
- `full_kb_rows_included=0`

Allowed shape:

- compressed summary text
- selected IDs
- sanitized fallback reason codes

Denied in `prompt_payload`:

- `seed_bundle_hash`
- `manifest_hash`
- `snapshot_hash`
- `index_hash`
- source paths or source-register location fields
- activation descriptors
- raw rows, raw graph objects, raw wiki text, or raw prompt text

### `retrieval_trace_log_telemetry_shadow_rollback`

`retrieval_trace_log_telemetry_shadow_rollback` is non-model-visible
operational metadata for retrieval traces, logs, local telemetry, shadow
observation, rollback records, and leakage checks. This class covers
non-prompt-payload artifacts only; it is not model-visible prompt context.

Allowed fields:

- `snapshot_version`
- `snapshot_hash`
- `resolved_intent`
- `selected_sample_ids`
- `selected_kb_rules`
- `selected_object_ids`
- `kb_context_summary`
- `fallback_reason_code`
- `payload_bytes`
- `candidate_pool_size`
- `normalized_score`
- `validator_gate_status`
- `leakage_gate_status`
- `full_kb_rows_included=0`

Allowed shape:

- sanitized trace fields
- selected IDs
- compact summary text
- numeric counters
- sanitized gate/fallback/leakage reason codes

Denied in `retrieval_trace_log_telemetry_shadow_rollback`:

- raw KB rows
- raw graph objects
- raw `prompt_body`
- full source register
- raw source text
- raw wiki page text
- overlay JSON
- quarantine records
- candidate seed rows as positive examples
- API keys, tokens, credential values, provider headers, local secret paths,
  or credential reference values

### `activation_descriptor`

`activation_descriptor` is the local install/startup artifact that binds the
verified runtime KB set. It is not model-visible prompt context and must not be
copied into runtime prompt payloads.

Allowed fields:

- `seed_bundle_hash`
- `manifest_hash`
- `snapshot_hash`
- `index_hash`
- `snapshot_version`
- `snapshot_name`
- `record_counts`
- `runtime_selection_predicates`
- `quarantine_exclusion_predicates`
- `candidate_exclusion_predicates`
- `last_known_good_snapshot`
- `activation_verified_at`

Allowed shape:

- local descriptor metadata
- integrity hashes
- activation predicates
- verified fallback pointer

Denied in `activation_descriptor`:

- raw KB rows
- raw graph objects
- raw `prompt_body`
- raw source text
- raw wiki page text
- overlay JSON
- API keys, tokens, provider headers, or credential values

Denied request-time fields and payloads:

- raw KB rows
- raw graph objects
- raw `prompt_body`
- full source register
- raw source text
- raw wiki page text
- overlay JSON
- quarantine records
- candidate seed rows as positive examples
- API keys, tokens, credential values, provider headers, or local secret paths
- full-table dumps

The v0.2 runtime exposure boundary is stricter than an internal snapshot
schema. Even if a snapshot stores richer internal rows for verification, the
runtime prompt payload remains summary-only plus selected IDs.

## Snapshot Activation Contract

Hash semantics:

- `seed_bundle_hash = manifest.content_hash`. It is the seed bundle digest
  recorded by the active seed manifest, currently using the
  `bundle-sha256:<digest>` form. It is not the activation descriptor digest.
- `manifest_hash` is the digest of the activation manifest descriptor. That
  descriptor binds `seed_bundle_hash`, `snapshot_hash`, `index_hash`, counts,
  runtime selection predicates, exclusion predicates, and fallback metadata.
- `snapshot_hash` is the digest of the selected immutable snapshot artifact,
  for example the selected SQLite snapshot file bytes or another approved
  deterministic snapshot artifact.
- `index_hash` is the digest of the runtime selection surface or index
  descriptor. It records which verified snapshot tables, views, predicates,
  and selection keys may be used by runtime consumers.

A snapshot activation descriptor must bind:

- `seed_bundle_hash`
- `manifest_hash`
- `snapshot_hash`
- `index_hash`
- `snapshot_version`
- `snapshot_name`
- record counts
- runtime selection predicates
- quarantine and candidate exclusion predicates
- `last_known_good_snapshot`

Activation timing:

- install or snapshot switch: full verification of manifest, snapshot, index,
  source minimum fields, counts, metadata, and selection predicates
- startup: light active check against the already verified descriptor
- runtime query: no rehash of manifest, snapshot, index, source files, or full
  tables

`manifest_hash` is not a synonym for `seed_bundle_hash`; both must be checked
when a candidate activation descriptor is verified. `index_hash` is a runtime
selection-surface digest. It does not imply GraphRAG, hybrid retrieval, rerank,
vector search, or any model-side default path.

## Failure Contract

On activation, startup, or index failure:

1. Keep the current verified active snapshot if it is healthy.
2. Otherwise activate a verified `last_known_good_snapshot`.
3. Otherwise fail closed with `no_kb_context`.

Failure behavior must not:

- query raw/wiki/schema layers
- scan full seed or snapshot tables to reconstruct context
- fetch network rescue data
- auto-ingest files
- promote quarantine, candidate, reserve, or negative fixtures
- run default LLM summarization
- silently continue with mismatched `seed_bundle_hash`, `manifest_hash`,
  `snapshot_hash`, or `index_hash`

## Validator Gates

Minimum v0.2 gates for this contract:

- `schema_object_required_fields_gate`: every object has the required envelope
  and type-specific fields.
- `schema_source_binding_gate`: every snapshot-eligible object binds to
  accepted source/wiki/seed identifiers.
- `snapshot_integrity_gate`: `seed_bundle_hash`, `manifest_hash`,
  `snapshot_hash`, and `index_hash` match before activation.
- `runtime_exposure_gate`: runtime payload contains only selected IDs,
  compressed summaries, sanitized status codes, and
  `full_kb_rows_included=0`.
- `positive_selection_gate`: reserve, candidate, quarantine, rejected, and
  negative-fixture objects cannot become positive few-shot samples.
- `router_eval_gate`: intent, BM25 pool, fallback, eval freshness, per-intent
  pass rates, and tail-failure constraints pass before auto-switch.
- `leakage_gate`: raw rows, `prompt_body`, source register dumps, raw graph,
  overlay JSON, secrets, paths, and provider credentials are absent.
- `fallback_gate`: failure resolves only to active snapshot,
  `last_known_good_snapshot`, or `no_kb_context`.

## Acceptance Checks

- A `prompt_sample` with `library_status=reserve` or few-shot ineligible status
  is blocked from positive runtime selection.
- A `prompt_failure_pattern` linked to a negative fixture can enter the
  snapshot only as `gate_only` or sanitized summary guidance.
- A `prompt_repair_strategy` cannot write back to seed, snapshot, Git, or raw
  wiki at runtime.
- A missing or mismatched `seed_bundle_hash`, `manifest_hash`,
  `snapshot_hash`, or `index_hash` blocks activation.
- A stale eval artifact blocks router auto-switch.
- A runtime payload containing raw `prompt_body`, raw rows, full source
  register, raw graph, overlay JSON, or secrets fails the leakage gate.
- A startup failure falls back only to a verified `last_known_good_snapshot` or
  `no_kb_context`.
- A runtime query performs no network rescue, source-file rehash, full-table
  scan, default LLM summarize, GraphRAG, hybrid search, or rerank path.

## Non-Goals

This contract does not authorize:

- changing `seed/v0.2/*.json`
- changing migrations
- changing SQLite snapshots
- changing `E:\codex\hope`
- default GraphRAG
- default hybrid search or rerank
- runtime network fetching
- runtime auto-ingestion
- default runtime LLM summarization
- exposing raw KB rows
- exposing raw `prompt_body`
- exposing the full source register
- exposing overlay JSON
- storing or exposing API keys, tokens, or credentials
