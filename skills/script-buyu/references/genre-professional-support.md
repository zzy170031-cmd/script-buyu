# 全题材的专业支持与选人

本页连接现有创作者方法与本项目需要的事实专业职责。具体题材、行业规则或方法选择存在缺口时按需读取，不整页注入。人物方法来自[现有索引](../data/genre-index.json)和[方法原件](../data/story-methods.json)，专业职责与取舍规则是本库编辑归纳，不代表真人顾问已经受聘。

## 分清三种职责

- 题材作家/导演：提供已定位的叙事方法，只解决本场问题。作品署名证明参与职责，不自动证明其每种建议或所有题材能力。
- 领域专业人士：依据可核实资格与原始资料，核当前时代、地域、法域、规则版本下的事实和允许行动；不能凭名气代替主张证据，也不能替人物选择主题、行动或结局。
- 本项目主笔与统稿：把建议写成唯一正文，决定采纳/改造/弃用，检查前后场。一个Agent可承担这些职责，不自动开多人会议，不让多个角色同时覆盖一段。

## 26类入口

每行两位分别示意作家方法、导演方法的现有入口，兼任身份照原登记；不是每剧固定二人组、完整名单或新增专家人数。使用时按题材查询核当前source/origin/method/binding状态，再读对应卡的具体适用条件；仅有静态姓名不算可用。全部现有人物与组合入口仍在[题材方法入口](genre-methods.md)，同机制和同人跨类不重复算能力。事实专业栏是需按项目核实的职责，不是已验证的各行业人员名单。

## 如何核实与纳入专业人士

从影响文本的具体问题查找：所需专业职责 → 相关代表工作/实际任职或研究资格 → 可阅读的本人或机构原始材料 → 支持的具体主张及版本条件。医学/法律等事实按适用地域与最新权威资料核实，不能只引用小说家观点。仅见姓名、简介或搜索摘要时仍是候选；来源冲突记disputed，正文不可访问记限制。原作分析标我方归纳，不冒充作者教学；转载共源不能当多份独立证据。

在现有research记录中增加一条必要应用即可：

```text
场景/问题｜创作方法ID或专业职责｜来源/定位/资格/版本｜事实状态
允许/不允许的行动或待定条件｜允许影响字段｜采用/改造/弃用及原因｜前后依赖
```

例：游戏故事的顾问资料证明某版本行动需要经过既定时限。统稿可让角色选择提前出发、改变已经授权的计划，或保留赶不上的代价；不能让部队因场面需要瞬移。关键时限未核实就记未知，不杜撰官方数字。历史戏剧中的动员方法只给叙事启发，不能证明真实年代的军制。专业资料纠正事实后，具体选择仍由本剧角色成立的动机和用户授权决定。

查询到候选并不自动永久入库。项目可用的证据记录留在项目内；只有用户要求维护Skill时，才按[来源维护](source-sync.md)更新库及资格/依赖。新增真实姓名需要核来源与适用贡献，不以每类需要支持为由无限凑数。

## 合并时不抢正文

按[统一选组与统稿](ensemble-writing.md)沿用一份当前正文与状态记录。先选能解决本场问题的一两种操作，需要更多时说明互补作用；这是阅读预算建议，不是硬配额。方法可不用，不按查询排序全部采用。

领域纠错指出事实边界与可行选项；对白建议不擅改承诺/拒绝；导演建议不新增目击或揭示；统稿检查采纳后的角色决定、代价和后继影响。同功能建议择一或合并，互斥建议不能平均混入正文。若专业事实与已锁设定冲突，按research和当前改编授权处理，不借顾问身份偷偷改主线。完整性检查按[文本试读](text-review.md)与[连续性](continuity-control.md)，不要求试拍制作。
