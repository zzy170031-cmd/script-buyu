# 故事剧本成稿形态

用户指定《铁城风云X414》十集故事剧本 v10 DOCX 只为说明“完整可阅读的故事剧本”这一产物类型，并明确不要求全部照搬。参考文件的故事内容、目录、人物、十集、三十分钟及现实/游戏比例不是新项目默认值。后续明确要求人物表增加人物形象提示词和对应参考图，按每部剧本内容设计，画风不固定。

## 默认一个 DOCX

以完整故事正文为主。按当前项目需要安排作品标题、必要项目设定、一句话故事、梗概、人物与弧线、世界规则和分集剧本。已有完整稿保留其有意采用的结构；不要为了套目录编造不必要设定。

用户只要单句、单场修订或创作诊断时，按指定范围和格式交付，不强制生成完整 DOCX。

人物表默认五列：人物ID、姓名、人物设定、人物弧线、人物形象提示词与参考图。最后一列放可复用的人物形象提示词及该人物实际生成或提供的参考图，一人一张。提示词包含适合本剧的时代/身份、外观、服装、神态、画风和构图要求；不把未设定的视觉补充冒充真实人物事实。无人故事不凭空造人物。用户明确要求纯文字时按其要求处理。

每集显示序号、集名和时长预算，每场标清场号、内外景、地点、时间及必要人物。按实际发生顺序交错写动作、对白、停顿与故事所需声音。对白明确说话者，动作写清主体、对象和后果；不能用分集概要或场次清单代替成稿。

不加入镜头表、运镜、模型参数、视频或场景生成提示词、专家过程、知识库摘抄、审计评分或后续制作方案。人物参考图的构图描述属于人物提示词。人物与场次ID可用于正文结构；样本ID、来源哈希等维护信息不混入用户成稿。

## 人物形象提示词与参考图

按 [character-visuals](character-visuals.md) 生成对应参考图，或使用用户提供的合适图片。嵌入前逐张查看原图，核对人物身份、外观、时代与服装；按原比例缩放。图片字节必须在 DOCX 包内，不能仅放外部链接。社区示例图不能冒充当前剧本人物图。生成失败时保留完整提示词并如实标明图片未完成，不声称已交付完整含图版。

先验证纯文字剧本及回读，再使用 `scripts/embed_character_images.py` 将已有图片写入新版本。含图稿需要逐页检查，严格纯文字回读会拒绝它；修改含图稿时用通用读取器和视觉核对恢复可见正文、人物图片映射，不静默删图或用旧 JSON 覆盖新改动。

```text
python scripts/embed_character_images.py --input deliverables/story-v1.docx --images work/character-images.json --output deliverables/story-v1-with-images.docx
```

内部映射如 `{"C01":{"prompt":"本人物实际使用的完整提示词","image":"images/c01.png"}}`，路径以映射文件所在目录为基准。纯图片旧映射仍可读取，但新完整交付应使用提示词与图片结构并覆盖全部人物。用户无需编写映射；嵌入脚本只排版，不联网、不生图、不覆盖已有文档。

## 交付前

核对用户请求的每集都有完整正文、人物与道具连续、事实与创作补写分清。时长称预算，不以字符数保证片长。纯文字结构检查、含图检查和真实渲染分别记录；没有完成渲染时如实说明。完整交付默认只给最终一个 DOCX，随后等待用户修改意见。
